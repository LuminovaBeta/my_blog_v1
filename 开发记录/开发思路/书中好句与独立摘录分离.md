# 书中好句与独立摘录分离

状态：需求与静态页面草图已调整；`library` 尚无书籍或摘录模型，本文件描述后续建表方案，不代表数据库已经迁移。

## 为什么分开

书中好句的主要入口是某本书的详情页。它必须属于一本书，方便查看这一整本书的句子、章节和页码。

独立摘录的主要入口是「独立摘录」列表。它保存电影、网页或日常遇到的句子，没有书籍关联。用户按内容类别、来源和关键词寻找它们。

前端不再把书中好句混进独立摘录列表；如果以后提供跨模块搜索，结果也应分别标明「书中好句」和「独立摘录」。

## 计划中的表

### `library_book`

一行代表当前用户的一本书。核心字段：`id`、`owner_id`、`title`、`author`、`description`、`category`、`cover`、`ebook_file`、`read_status`、`progress_percent`、`created_at`、`updated_at`。书籍详情页是书中好句的入口。

### `library_bookquote`

一行只代表某本书的一句好句：

| 字段 | 用途 |
| --- | --- |
| `id` | 主键 |
| `book_id` | 必填的外键，指向 `library_book`，`related_name='quotes'` |
| `content` | 好句原文，必填 |
| `chapter` | 章节名称，可空 |
| `page_number` | 纸书或 PDF 页码，可空 |
| `location` | EPUB 等无固定页码时的位置，可空 |
| `translation` | 译文，可空 |
| `note` | 个人感想，可空 |
| `created_at`、`updated_at` | 记录与修改时间 |

不另存 `owner_id` 和 `source_title`：所有权及书名从所属书籍取得，避免两份数据不一致。查询、修改和删除都需要以 `book__owner=request.user` 校验权限。

删除有好句的书时，建议使用 `PROTECT` 阻止误删，先让用户决定保留、转移或删除这些好句。不要静默把它们变成独立摘录。

### `library_independentexcerpt`

一行代表一条不依赖书架的摘录：

| 字段 | 用途 |
| --- | --- |
| `id` | 主键 |
| `owner_id` | 必填的外键，指向当前用户 |
| `content` | 摘录原文，必填 |
| `category` | 英文、现代中文、文言文、其他 |
| `source_type` | 电影、网页、其他；不含书籍 |
| `source_title` | 作品或出处名称，可空 |
| `attribution` | 说话者、作者等，可空 |
| `translation` | 译文，可空 |
| `note` | 个人感想，可空 |
| `created_at`、`updated_at` | 记录与修改时间 |

此表不设置 `book_id`。书籍来源的句子应先选择或创建书籍，再保存为 `BookQuote`。独立摘录只通过 `owner=request.user` 查询。

### `talks_talkentry`

谈资保留在独立的 `talks` App，保存自己的经历与观察。它与书籍、两类摘录都没有外键关系。

## 页面入口

```text
我的书架 → 书籍详情 → 这本书的好句 → 添加本书好句
独立摘录 → 全部独立摘录 → 添加独立摘录
我的谈资库 → 日常见闻与聊天素材
```

当前 `/library/preview/` 和 `/library/excerpts/` 仍是静态示例页面，没有保存能力。后续实现模型与接口时再创建迁移，并按上述边界接入真实数据。
