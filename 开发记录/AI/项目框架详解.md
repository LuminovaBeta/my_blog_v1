# My Blog 项目框架详解

## 1. 项目是什么

这是一个基于 Django 开发的个人博客与内容管理系统。

它不仅能展示文章，还包含以下功能：

- 用户注册、登录和个人资料管理
- Markdown 文章编写、修改与发布
- 文章草稿和自动保存
- 文章密码访问与 Session 解锁
- 评论、回复、点赞和收藏
- 阅读量、站点数据和 48 小时排行榜统计
- 头像、文章封面和正文图片管理
- 个人中心与内容工作台
- Django 管理后台

项目整体采用：

> Django 服务端渲染 + Vue 局部交互 + MySQL 数据存储

它不是一个前后端完全分离的单页应用。页面主体由 Django 生成，Vue、Axios、Element Plus、jQuery 和 Editor.md 用来增强页面交互。

## 2. 用餐厅理解整个项目

可以把这个博客系统想象成一家餐厅：

| 项目组成 | 餐厅角色 | 实际作用 |
| --- | --- | --- |
| 浏览器 | 顾客 | 请求查看文章、保存草稿或发表评论 |
| URL 路由 | 前台接待员 | 判断请求应该交给哪个功能处理 |
| View 视图 | 厨师 | 执行业务逻辑 |
| Model 模型 | 仓库管理员 | 查询或保存数据库数据 |
| MySQL | 仓库 | 长期保存用户、文章、草稿和评论 |
| Template 模板 | 摆盘人员 | 把数据组合成 HTML 页面 |
| Vue/JavaScript | 服务员 | 处理按钮点击、异步保存和页面提示 |
| static | 餐厅装修 | 保存 CSS、JavaScript、图标和前端库 |
| media | 用户文件库 | 保存头像、封面和文章图片 |

例如，用户打开 `/article/12/` 时：

1. 浏览器向服务器请求编号为 12 的文章。
2. Django URL 路由找到文章详情功能。
3. View 查询数据库中的文章。
4. View 检查文章是否存在、是否发布、是否需要密码。
5. Model 从 MySQL 中读取对应数据。
6. Template 把文章数据放入 HTML。
7. 浏览器收到并显示页面。
8. JavaScript 将 Markdown 转为正文，并生成文章目录和阅读位置高亮。

最重要的一条主线是：

```text
浏览器发出请求
    ↓
URL 找到处理者
    ↓
View 执行业务逻辑
    ↓
Model 操作数据库
    ↓
Template 生成页面，或者 API 返回 JSON
    ↓
JavaScript 增强页面交互
```

## 3. 项目目录结构

```text
my_blog_v1/
├── manage.py              Django 项目操作入口
├── pyproject.toml         Python 版本、依赖和项目配置
├── uv.lock                Python 依赖锁定文件
├── package.json           Sass 编译命令和前端工具配置
│
├── my_blog/               Django 项目级配置
├── app01/                 博客核心业务和数据库模型
├── api/                   异步请求接口
├── templates/             HTML 页面模板
├── static/                CSS、SCSS、JS、图标和第三方库
├── media/                 用户上传的头像、封面和正文图片
├── scripts/               数据备份、恢复等辅助脚本
└── 开发记录/              项目设计与开发说明
```

### 3.1 `my_blog/`：项目总配置

这个目录负责整个 Django 项目的公共配置，主要文件包括：

- `settings.py`：数据库、模板、中间件、静态资源、语言和时区等配置。
- `urls.py`：网站最外层 URL 路由。
- `wsgi.py`：传统 WSGI 部署入口。
- `asgi.py`：ASGI 部署入口，也为以后使用异步功能提供基础。

### 3.2 `app01/`：核心业务应用

这个目录是博客的主要 Django App，包含：

- 数据库模型
- 页面 View
- Django Admin 配置
- 模板标签和过滤器
- 中间件
- 工具函数
- 数据库迁移
- 管理命令

### 3.3 `api/`：JSON 接口

这个目录负责处理前端异步请求，例如：

- 登录和注册
- 新建、编辑和保存文章
- 新建、更新和删除草稿
- 验证文章密码
- 评论、点赞和收藏
- 上传文章图片
- 管理头像和封面
- 修改密码、邮箱和个人资料

API 一般不返回完整 HTML，而是返回 JSON，例如：

```json
{
  "code": 0,
  "message": "保存成功",
  "data": {}
}
```

### 3.4 `templates/`：页面模板

这里存放 Django HTML 模板。模板可以读取 View 提供的数据，并通过继承复用公共页面结构。

公共页面通常继承网站基础模板，后台页面通常继承后台基础模板。这样导航栏、页脚和侧边栏只需要在父模板中维护一次。

### 3.5 `static/` 与 `media/`

`static` 保存开发者提供的固定资源：

- CSS 和 SCSS
- JavaScript
- 图标和默认图片
- Vue、Axios、Element Plus
- Editor.md
- 明暗主题资源

`media` 保存用户在运行过程中上传的文件：

- 用户头像
- 文章封面
- Markdown 正文图片

简单理解：`static` 属于程序，`media` 属于业务数据。

## 4. Django 的 MVT 架构

Django 使用 MVT 架构：

- Model：数据模型
- View：业务逻辑
- Template：页面模板

它和常见的 MVC 思想很接近。

### 4.1 Model：定义数据

Model 位于 `app01/models.py`，用 Python 类描述数据库中的表和字段。

例如文章模型会描述一篇文章具有：

- 标题和摘要
- Markdown 正文
- 作者、来源和原文链接
- 分类和标签
- 封面
- 创建时间和修改时间
- 发布状态和推荐状态
- 阅读、评论、点赞、收藏数量
- 文章访问密码

Django 会将模型转换为 MySQL 表。开发时通常通过 Django ORM 查询数据，而不是直接拼写 SQL。

```python
Articles.objects.filter(status=1)
```

这段代码表示查询全部已发布文章。

### 4.2 View：处理业务

项目中有两类 View：

1. 页面 View：返回完整 HTML 页面，例如首页、文章页和个人中心。
2. API View：返回 JSON，例如自动保存草稿、点赞和评论。

View 通常负责：

- 检查用户身份和权限
- 验证前端提交的数据
- 调用 Model 查询或修改数据库
- 组织页面需要的数据
- 选择模板或返回 JSON

### 4.3 Template：生成页面

模板是带有 Django 模板语法的 HTML。

```html
<h1>{{ article.title }}</h1>
```

Django 会将 `article.title` 替换成真实标题，再把最终 HTML 发给浏览器。

## 5. URL 路由

URL 路由相当于网站内部地图，负责把不同地址交给不同 View。

常见地址包括：

```text
/                         首页
/search/                  搜索页面
/article/12/              查看编号为 12 的文章
/backend/                 个人中心
/backend/add_article/     新建文章
/backend/drafts/          草稿列表
/api/...                  异步 API
/admin/                   Django 管理后台
```

根路由在 `my_blog/urls.py`。以 `/api/` 开头的请求会继续交给 `api/urls.py` 分发。

## 6. 核心数据库模型

### 6.1 `UserInfo`：用户

这是基于 Django 用户系统扩展的自定义用户模型。

一个用户可以：

- 发布多篇文章
- 创建多个草稿
- 发表多条评论
- 收藏多篇文章
- 选择自己的头像

### 6.2 `Articles`：正式文章

这是系统最核心的数据模型，保存已经发布或正式管理的文章。

文章正文保存的是 Markdown 源文本，阅读页面再将其转换为 HTML。

### 6.3 `ArticleDraft`：文章草稿

草稿是编辑过程中的工作副本，分为两种：

```text
新文章草稿
    没有关联正式文章

已有文章的修改草稿
    关联一篇正式文章
```

草稿保存标题、摘要、正文、分类、标签、封面、密码操作状态、修改时间和版本号。

版本号用于避免多个浏览器窗口同时编辑时，旧页面覆盖新内容。

### 6.4 `Tags`：文章标签

文章和标签是多对多关系：

- 一篇文章可以有多个标签。
- 一个标签可以属于多篇文章。

### 6.5 `Comment`：评论

评论属于一篇文章和一个用户。评论还可以指向另一条父评论，从而实现回复层级。

### 6.6 `ArticleView`：阅读记录

它记录每一次阅读对应的文章和时间，因此系统不仅能保存总阅读量，还能准确统计最近 48 小时的阅读排行。

### 6.7 `Cover` 和 `Avatars`

它们分别管理文章封面和用户头像。数据库保存文件路径，真实文件存放在 `media` 中。

### 6.8 主要数据关系

```text
用户 1 ─── N 正式文章
用户 1 ─── N 草稿
用户 1 ─── N 评论
用户 N ─── N 收藏文章

文章 1 ─── N 评论
文章 1 ─── N 阅读记录
文章 N ─── N 标签
文章 N ─── 1 封面

草稿 0/1 ─── 1 正式文章
评论 0/1 ─── N 子评论
```

其中 `1` 表示一条，`N` 表示多条，`0/1` 表示可以没有，也可以有一条。

## 7. 文章和草稿流程

### 7.1 新建文章

```text
进入新建文章页面
    ↓
填写标题、正文、标签等内容
    ↓
前端调用草稿 API
    ↓
保存 ArticleDraft
    ↓
继续编辑或离开页面
    ↓
点击正式发布
    ↓
创建 Articles 数据
    ↓
清理对应草稿
```

因此用户在没有发布的情况下离开页面，仍然可以在“文章草稿”中找回内容。

### 7.2 编辑已有文章

```text
打开正式文章的编辑页面
    ↓
检查是否存在关联草稿
    ├── 有草稿：优先加载草稿
    └── 无草稿：加载正式文章
    ↓
修改内容并自动暂存
    ↓
确认保存后更新正式文章
```

这样编辑中的内容不会立刻覆盖已经发布的版本。

### 7.3 草稿版本控制

假设窗口 A 和窗口 B 都加载草稿版本 5：

1. 窗口 A 保存成功，服务器版本变为 6。
2. 窗口 B 仍然携带版本 5 保存。
3. 服务器发现版本不一致，拒绝旧数据。

这是一种简单的乐观锁，可以防止无意覆盖。

## 8. 文章密码与 Session 解锁

文章可以设置访问密码。访问流程如下：

```text
打开文章
    ↓
文章是否设置密码？
    ├── 没有：直接显示正文
    └── 有：检查 Session 是否已解锁
              ├── 已解锁：显示正文
              └── 未解锁：显示密码验证页
```

Session 可以理解为服务器为当前浏览器保存的一份短期状态。

密码验证成功后，服务器在 Session 中保存解锁标记。这个标记与文章当前密码状态绑定，因此文章密码改变后，旧解锁状态会失效。

系统还限制短时间内的连续失败次数，以降低暴力猜测密码的风险。

文章未解锁时：

- 不返回正文
- 不返回评论
- 不生成正文目录
- 不增加有效阅读量

后台编辑文章时也不会回显原密码，只显示当前是否已设置密码，并提供保留、设置新密码或移除密码三个操作。

## 9. 首页和文章阅读页

### 9.1 首页

首页从数据库读取：

- 已发布文章列表
- 文章分类
- 标签云
- 已发布文章数量
- 总阅读量
- 已使用标签数量
- 网站运行天数
- 最近 48 小时阅读排行榜

48 小时排行榜依赖 `ArticleView` 的真实阅读时间记录，所以只能准确统计启用该功能之后的数据。

友情链接目前仍偏向模板中的静态配置，项目虽有相关导航模型，但还没有完整接入首页管理流程。

### 9.2 阅读页面

文章正文以 Markdown 保存。浏览器通过 Editor.md 将 Markdown 转成 HTML。

JavaScript 会读取一级到四级标题并生成浮动目录。页面滚动时，它会判断当前阅读区域，自动高亮相应目录项。

每个标题都会生成唯一定位标识，因此即使多个标题名称相同，也不会同时错误高亮。

## 10. 个人中心与内容工作台

个人中心已经不只是资料页面，也承担内容管理工作台的作用。

### 数据概览

- 已发布文章
- 草稿数量
- 收到的评论
- 收藏文章
- 总阅读量

### 快捷操作

- 新建文章
- 查看草稿
- 管理文章
- 管理封面

### 最近编辑

正式文章和草稿合并展示，包含：

- 标题
- 已发布或草稿状态
- 最后修改时间
- 阅读量
- 继续编辑入口

### 最近互动

展示最近收到的评论、所属文章、评论用户、评论时间和回复入口。

### 收藏文章

收藏数据来自用户与文章之间真实的多对多关系，不是固定演示数据。

## 11. 前端技术的职责

### 11.1 Django Template

负责页面结构和第一次打开页面时的数据，例如文章列表、登录状态、草稿内容和评论列表。

### 11.2 Vue 3

Vue 以局部增强方式运行在 Django 页面中，主要负责：

- 表单数据绑定
- 编辑器页面状态
- 标签和封面选择
- 草稿保存状态
- 抽屉和弹窗
- 点赞、收藏和密码验证交互

Django 和 Vue 默认都使用双大括号，所以项目将 Vue 的插值符号调整为 `[[ ]]`，避免模板冲突。

### 11.3 Axios

Axios 用于向 API 发送异步请求。请求拦截器会为修改数据的请求添加 CSRF Token，响应拦截器负责统一读取响应数据。

### 11.4 Element Plus

提供按钮、表单、输入框、抽屉、标签、对话框和消息提示等界面组件。

### 11.5 jQuery 与 Editor.md

jQuery 负责部分 DOM 操作、动画和旧插件支持，Editor.md 负责 Markdown 编辑与渲染。

### 11.6 SCSS

SCSS 是更适合维护的 CSS 写法。源码位于 `static/scss`，通过 npm 命令编译到 `static/css`。

Node.js 在当前项目中主要用于编译 Sass，而不是打包整个 Vue 应用。

## 12. 中间件与公共上下文

项目有一个自定义中间件，用于解析非 GET 请求中的 JSON，并将结果保存到 `request.data`，方便 API 读取。

项目还有公共 Context Processor，用于向所有模板提供 JavaScript 库地址。它可以根据配置选择本地资源或 CDN 资源，避免每个模板重复配置。

## 13. 身份、权限和安全机制

项目使用 Django 自带认证系统和自定义 `UserInfo`。

| 操作 | 基本权限要求 |
| --- | --- |
| 浏览公开文章 | 普通访客 |
| 验证文章密码 | 普通访客 |
| 评论和收藏 | 登录用户 |
| 修改个人资料 | 当前登录用户 |
| 新建和管理文章 | 管理权限用户 |
| 直接保存文章正文 | 已登录超级用户 |
| Django 后台 | 后台管理用户 |

修改数据的请求还要经过 CSRF 验证。CSRF 用于防止用户登录后，被其他恶意网站利用身份偷偷提交修改请求。

当前项目在正式部署前仍需完成以下安全整理：

1. 将 `SECRET_KEY`、数据库密码和邮件授权信息移到环境变量。
2. 生产环境关闭 `DEBUG`。
3. 将 `ALLOWED_HOSTS` 设置为实际域名。
4. 使用 HTTPS，并配置安全的 Cookie 选项。
5. 使用 Nginx 等服务器处理静态文件和媒体文件。

任何开发文档和 Git 提交中都不应该记录真实密码或密钥。

## 14. 数据库迁移

迁移文件位于 `app01/migrations`，可以理解为数据库结构的版本记录。

新增草稿模型的典型过程是：

1. 在 `models.py` 中定义 `ArticleDraft`。
2. 执行 `makemigrations` 生成迁移文件。
3. 执行 `migrate` 更新 MySQL。

迁移文件应该提交到 Git，这样其他环境才能创建相同的数据库结构。

当前迁移已经包含草稿、阅读记录、密码字段和草稿密码操作状态等变化。

## 15. 开发一个新功能时要考虑哪些层次

以“文章举报”为例，一个完整功能通常包括：

1. **Model**：保存举报人、文章、原因、时间和状态。
2. **Migration**：把数据结构同步到数据库。
3. **URL**：增加举报接口地址。
4. **View/API**：验证并保存举报请求。
5. **Template**：增加举报按钮和弹窗。
6. **JavaScript**：通过 Axios 提交数据。
7. **Admin**：允许管理员查看和处理举报。
8. **Test**：验证权限、重复举报和异常数据。

因此，一个功能通常是一条完整链路：

```text
数据结构
→ 后端业务
→ URL 路由
→ 页面模板
→ 前端交互
→ 权限安全
→ 自动化测试
```

## 16. 项目运行方式

基本运行流程：

```text
安装 Python 依赖
    ↓
创建和配置 MySQL 数据库
    ↓
执行数据库迁移
    ↓
创建超级用户
    ↓
启动 Django
```

常用命令：

```powershell
uv sync
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

修改 SCSS 后执行：

```powershell
npm run sass
```

开发期间持续监听 SCSS：

```powershell
npm run watch
```

## 17. 项目目前的优点

- 使用自定义用户模型，方便继续扩展。
- 页面 View 与 API 职责基本分离。
- 草稿和正式文章分开保存。
- 同时支持新文章草稿和已有文章的修改草稿。
- 使用版本号降低草稿被旧窗口覆盖的风险。
- 文章密码使用安全哈希保存，不在后台回显。
- 使用 Session 保存临时解锁状态。
- 正文保存接口有登录、超级用户和 CSRF 校验。
- 阅读记录支持真实时间范围统计。
- 个人中心已经具备内容工作台结构。
- 页面通过模板继承统一管理。

## 19. 面向初学者的口头介绍

可以用下面这段话介绍项目：

> 这是一个使用 Django 开发的个人博客系统。浏览器发出请求后，Django 的 URL 路由会把请求交给对应的 View。View 负责处理业务逻辑，并通过 Model 从 MySQL 中查询或保存数据。如果用户访问普通页面，View 会把数据交给 HTML 模板生成页面；如果用户执行保存草稿、评论或收藏等操作，API 会返回 JSON，再由 Vue 和 Axios 更新页面。
>
> 文章使用 Markdown 编写，并且支持自动保存草稿。新文章的草稿可以独立存在，修改旧文章时，草稿会和原文章建立关联。正式保存后，草稿内容会更新到文章。文章还可以设置访问密码，验证成功后使用 Session 记录临时解锁状态。
>
> 项目的固定前端资源放在 static，用户上传的头像、封面和正文图片放在 media。数据库结构由 Django Model 定义，再通过 Migration 同步到 MySQL。个人中心负责展示文章、草稿、评论、收藏和阅读统计，相当于一个内容管理工作台。

初学者只要先记住下面这条主线，就能逐步理解整个项目：

```text
浏览器发请求
→ URL 找负责人
→ View 处理业务
→ Model 操作数据库
→ Template 生成页面或 API 返回数据
→ JavaScript 增强交互
```
